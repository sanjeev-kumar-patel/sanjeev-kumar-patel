# Sanjeev Kumar Patel

**Difficulty:** Medium, with a hard follow-up  
**Topics:** `C++` `Graphs` `Dynamic Programming` `Binary Search` `Full-Stack` `Machine Learning`

### Description

You are given a CS undergrad at NIT Srinagar (class of 2028) who learns best when something is actually broken.

Return someone who can look at a new problem, see its shape, and explain why the number at the end is right.

### Example 1

```
Input:  a slow query, a weird bug, a half-working schema
Output: one lost weekend, one fixed thing
Explanation: Problems where the answer is sitting in a tutorial
three tabs over don't count. They don't teach me much.
```

### Example 2

```
Input:  a tutorial that says "just call .fit()"
Output: a notebook where I derived the gradient by hand first
Explanation: I don't trust a model until I've seen the math.
It takes longer. It's the only way I end up believing the number.
```

### Example 3

```
Input:  a problem I've never seen
Output: a pattern, not just an accepted submission
Explanation: 400+ solved on LeetCode and GeeksforGeeks, mostly in C++.
The count was never the point. How fast I see the shape is.
```

### Constraints

- Learn the probability, linear algebra and statistics before the library.
- Do not rush past DSA. Everything else sits on top of it.
- Time complexity: weekends are fine.
- Space complexity: as many browser tabs as it takes.
